Headless APIs

Every component in this guide has a REST surface. Here are the modules, their base URIs, the ID convention each one uses, and the feature flags that make endpoints appear to not exist.

The modules

All paths resolve relative to http://localhost:${PORT}. Basic auth (test@liferay.com:test) works for local exploration and bypasses scope checks entirely, which is why a call that works in curl can still fail from a CET.

ERC vs numeric ID — this costs everyone an hour

headless-admin-site keys subresources by external reference code: /sites/{siteExternalReferenceCode}/site-pages. A numeric site ID returns 404, which reads like "the endpoint does not exist" and sends you hunting a feature flag.

headless-admin-content and headless-delivery, in the same product, use the numeric {siteId}.

Error codes, and what they usually actually mean

StatusDocumented meaningMost common real cause
400Validation errorRead the title in the problem detail — it names the field
401Not authenticatedThe OAuth registration, not the scopes
403ForbiddenScope too narrow, or a missing Service Access Policy for anonymous calls
404Not foundA feature flag is off, or you passed a numeric ID where an ERC was required
409ConflictDuplicate name or ERC
500Server errorCheck bundles/logs/liferay.<date>.log
200 with an empty list—A permission gap. This is the dangerous one.

Discovering endpoints

GET /o/<module>/v1.0/openapi.json

The spec gives you exact paths and payload shapes. It does not tell you the base URI conventions, the feature-flag gates, or the OAuth scopes — those come from the table above.

How it connects

  • Objects — the generated entry API
  • Pages — creating layouts programmatically
  • CETs — what calls these, and with which token
  • Service Access Policies — the gate before permissions
  • Site initializers — the declarative alternative
  • Fragments — browser-side calls run as the visitor

Traps

Editing a fragment over the API does not change any page using it

Liferay copies fragment code into each page's fragment instance. A PUT updates the library entry and leaves every existing placement untouched. Reprovision to apply fragment changes.

Basic auth hides scope problems

Your curl as test@liferay.com has full admin rights and evaluates no scopes. The same call from a CET with a narrow token returns 403. Test the CET path before declaring it works.

One section fragment breaks the fragment listing

A single fragment declaring "type": "section" makes the whole set's listing return 400. Verified on 2026.Q2.
