In one sentence

A Web Content article (internally a Journal Article) is one record of editorial content: a title plus values for the fields its Content Structure defines, rendered by a Web Content Template and placed on a page.

What it actually is

Three things are always involved, and confusing them is the #1 source of "why is my content blank":

Content Structure ──── defines what fields exist ────▶ "Title, Subtitle, Image, Body, Author" ▲ │ │ an article picks one structure │ filled in by an editor │ ▼ Web Content Article ───────────────────────────────▶ the actual values for one news item │ │ rendered by ▼ Web Content Template ──── FreeMarker markup ────▶ the HTML a visitor sees

The structure is the shape. The article is the data. The template is the look. You can swap the template without touching a single article, and that is the whole point of the split.

Basic vs structured

KindWhat it isUse when
Basic Web ContentOne rich-text body, no structure chosenFree-form prose: an "About us" blurb, a legal notice. Editors get a WYSIWYG and nothing to fill in wrong.
Structured Web ContentArticle bound to a Content StructureAnything repeated with consistent parts: news, press releases, staff profiles, product cards. Enables reliable collections and display pages.
Rule of thumb

If you will ever want to list these items, filter them, or give each one its own URL, it must be structured. Basic web content is a dead end for anything but a one-off block of prose.

What you get for free

  • Versioning — every save creates a version (1.0, 1.1, …). Editors can compare and restore.
  • Translation — per-locale values on each field, with a translation UI and a per-locale completion state.
  • Scheduling — display date, expiration date, review date.
  • Workflow — attach a Kaleo workflow so articles need approval before going live.
  • Asset behaviour — categories and tags, related assets, ratings, comments, and search indexing come along automatically.
  • Folders — for organisation and per-folder permissions/workflow.

An Object gives you none of the first four. That is the real dividing line between the two.

How it connects to everything else

  • Content Structure — defines its fields
  • Web Content Template — renders it
  • Collections — list many articles
  • Display Page Template — one URL per article
  • Fragments — map article fields into page markup
  • Categories — what collections filter on
  • Workflow — approval before publish
  • Headless APIs — create and read articles

In source control

A site initializer carries articles as a pair of files under journal-articles/: a .json naming the structure and folder, and an .xml holding the field values.

journal-articles/leadership/leadership_profile_8.json
{
	"ddmStructureKey": "Leadership Profile",
	"folder": "Leadership",
	"name": "Nigel Cook"
}
journal-articles/leadership/leadership_profile_8.xml
<root available-locales="en_US" default-locale="en_US" version="1.0">
	<dynamic-element field-reference="name" index-type="keyword" name="name" type="text">
		<dynamic-content language-id="en_US"><![CDATA[Nigel Cook]]></dynamic-content>
	</dynamic-element>
	<dynamic-element field-reference="image" name="image" type="image">
		<dynamic-content language-id="en_US">
			<![CDATA[[$DOCUMENT_JSON:/site-initializer/documents/group/Leadership/leader.png$]]]>
		</dynamic-content>
	</dynamic-element>
</root>

Note the [$DOCUMENT_JSON:…$] token: media references resolve at provisioning time, so the XML never hardcodes an ID. Same idea as every other initializer token.

Traps

Changing a structure after articles exist

Removing or renaming a field on a live structure orphans the data already stored under that field reference in every article's XML. Add fields freely; removing them is a migration, not an edit.

Guest cannot read what you can

A logged-out visitor needs both a Service Access Policy (for Headless reads) and a VIEW grant. Your article looks fine to you and returns nothing to them. Verify with an unauthenticated curl, never with your own session.

Basic content in a structured slot

A dynamic collection filtered to a structure will silently skip basic articles — they have no structure, so they do not match. The list just comes back shorter than expected.
