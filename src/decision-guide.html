"I need to store some data"

SituationUseWhy not the other one
Marketing copy, news articles, hero text, FAQs — written by editors, translated, versioned, approved Web Content + Content Structure An Object gives you no versioning, no translation UI, and no rich-text editing worth the name
Leave requests, tickets, assets, employees — records with fields, relations, status, validation Object Web Content has no relationships, no queryable fields, and no per-record permissions worth using
PDFs, images, videos, policy documents Documents & Media Storing binaries as Object fields loses the preview, the checkout/versioning, and the CDN path
A fixed list of options: status values, departments, priorities Picklist (list type definition) Hard-coding the list in a fragment means editors cannot change it
Labels used to group and filter content across types Categories (vocabulary) or tags A field on the structure cannot be filtered on by a dynamic collection
Data that lives in SAP, an external DB, or another SaaS Object Entry Manager CET Copying the data into Liferay means you now own a sync problem

Cost ladder — reach for the cheapest thing that works

cheapest ─────────────────────────────────────────────────────────────▶ most expensive Style book token Fragment config Fragment + JS Web content template Object action (no-code) │ │ │ │ │ └── no deploy ────┴── no deploy ────┴─ reprovision ─────┴── no deploy ─────────┘ Client Extension (CET) OSGi module ├─ deploy, own lifecycle ├─ deploys into the JVM ├─ works on SaaS ├─ self-hosted only └─ survives upgrades └─ re-test every upgrade

Most "we need a customisation" requests are solved one or two rungs to the left of where the team starts. Ask what the cheapest rung that satisfies the requirement is, then stop there.

Common mistakes, and what to do instead

MistakeInstead
Pasting a whole HTML template into one fragment or custom elementSplit into header/footer fragments on a master page, plus body fragments on the content page
Building one page per news article by handOne display page template and a collection for the index
Fetching a picklist over REST from a public form's JavaScriptShip the options in the fragment markup — Guest gets 403 on that endpoint (why)
Counting submissions in the browser on a public pageDenormalize with an Aggregation field — Guest reads 0 and the arithmetic silently lies
Putting a siteInitializer and a themeCSS in one CET projectSibling projects — the classifications cannot mix (rule)
Writing an OSGi module because "we need custom logic"Check the CET table above first; most cases are a microservice CET
Editing the live site as the source of truthEdit the initializer tree and reprovision
