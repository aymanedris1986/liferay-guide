The one-paragraph version

Liferay separates where data lives from how it looks from where it appears. Data lives in Web Content, Objects, or Documents. Look is supplied by Fragments, templates, and style books. Placement happens on Pages. Collections are the wire that carries "many items" from the data side to the look side. Client Extensions are how you add your own code without touching the platform.

Three vocabularies that trip everyone up

Liferay reuses three words for different things. Get these straight and half the confusion disappears:

WordIt can mean…Disambiguated on
Template A FreeMarker script that renders content fields; or a reusable page layout; or the per-item landing page; or a master header/footer; or an email body. Five unrelated things. All template types
Collection A saved list of items (Asset List); or the fragment that renders that list; or a fragment collection, which is just a folder of fragments and has nothing to do with the other two. Collections
Structure A Content Structure (fields for a web content article, the classic DDM kind); or an Object definition (fields for a database record); or a Document Type / Metadata Set; or, in the new object-based CMS (see below), a "content structure" that is really an Object definition underneath. Content Structures vs Objects

Two CMSes in 2026: classic and new

You need to know about this before you read anything else. Since 2025.Q4 Liferay has been shipping a second content management system next to the one this guide mostly covers:

Classic CMS (this guide's default)New "headless" CMS
StorageJournal articles + DDM structures (Web Content, Content Structures)Built on Objects: content structures are object definitions, content items are object entries
OrganisationSites, folders, Asset LibrariesSpaces
StatusSupported, but in maintenance mode since 2026.Q1: fixes continue, new features go to the new CMSBeta in 2025.Q4 and released behind the CMS feature flag (LPD-17564) in 2026.Q1. GA without a flag only from 2026.Q3

On 2026.Q2, which this workspace runs, the new CMS is off unless someone enables the flag. Liferay's position is that the two run in parallel and classic sites keep working. Build Badael on the classic stack unless there is a deliberate decision to adopt the new one, and don't mix the two for the same content type. A trap to watch for: search results and learn.liferay.com now often show the new CMS's "Content Structures" pages first, and their field settings (ERC, Mandatory, picklists, "Select Related Content") are not the classic structure builder's.

How to regenerate these pages

Page bodies live in src/; the shared shell (head, nav, footer) is applied by build.sh. Edit a body, then:

cd liferay-guide    # the folder that contains build.sh
bash build.sh

Adding a page means dropping src/<slug>.html (first two lines are <!--title: …--> and <!--subtitle: …-->) and adding one line to the PAGES array in build.sh.
