1. Web Content Template FreeMarker

Bound to a Content Structure. Receives one article's field values, emits HTML. Full detail on its own page: Web Content Templates.

Relations: structure supplies the fields · articles supply the data · used by the Web Content Display widget, by collections, and inside display pages.

In a site initializer: ddm-templates/<name>/ddm-template.json (ddmTemplateKey, ddmStructureKey, name) plus ddm-template.ftl.

2. Display Page Template

The one that saves the most work and is most often missed. A display page template is bound to a content type + subtype, and every item of that type automatically gets its own URL rendered through it.

EntitycontentTypecontentSubtype
Web Contentcom.liferay.journal.model.JournalArticlethe content structure's key ({"subtypeKey": "ARTICLE"})
Object entrycom.liferay.object.model.ObjectDefinition#<id>. In an initializer, use [$OBJECT_DEFINITION_CLASS_NAME:<ObjectName>$](none) — the class name already identifies the object
Blog postcom.liferay.blogs.model.BlogsEntry(none)
Documentcom.liferay.portal.kernel.repository.model.FileEntryoptional: a document type

In a site initializer this is layout-page-templates/display-page-templates/<name>/display-page-template.json plus the usual page-definition.json:

{
	"contentSubtype": { "subtypeKey": "BADAEL-NEWS" },
	"contentType": { "className": "com.liferay.journal.model.JournalArticle" },
	"defaultTemplate": true,
	"name": "News Article"
}
Each object is its own class name

Every object definition registers its own class name, com.liferay.object.model.ObjectDefinition#<objectDefinitionId>. The ID differs per environment, which is why initializers use the OBJECT_DEFINITION_CLASS_NAME token. A plain com.liferay.object.model.ObjectEntry matches nothing.

Inside it, fragments map to the current item rather than to a fixed article. In a FreeMarker fragment the item is available as:

[#assign entryId = (request.getAttribute("INFO_ITEM").objectEntryId)! /]

Only one template per contentType+contentSubtype can be the default; that default is what an item's URL uses when no template is named in the path.

The pattern this replaces

500 news articles = 1 display page template + 1 collection for the index. Not 500 hand-built pages. If anyone on the project is creating pages per record, this is the fix.

3. Page Template

A saved page layout that editors pick when creating a new page. It is copied into the new page at creation time.

Copy, not link

Editing a page template later does not change pages already created from it. If you need changes to propagate, the content belongs on a master page instead, which is a live link.

Page templates always belong to a page template set (collection). In a site initializer that becomes layout-page-templates/page-templates/<set>/page-template-collection.json, with one folder per template holding a page-template.json and a page-definition.json. There are two flavours: content page templates (fragments, the default) and widget page templates (a classic layout plus portlets).

4. Master Page Template

The persistent frame around content pages: header, navigation, footer. Each page that uses the master injects its own content into the master's DropZone. The DropZone's fragmentSettings can also limit which fragments editors may drop into pages that use this master.

In an initializer: layout-page-templates/master-pages/<master-name>/ containing master-page.json (just {"name": "…"}) and page-definition.json. The directory name is the master's key.

{
	"pageElement": {
		"pageElements": [
			{ "definition": { "fragment": { "key": "site-header", "siteKey": "[$GROUP_KEY$]" } }, "type": "Fragment" },
			{ "definition": { "fragmentSettings": { "unallowedFragments": [] } }, "type": "DropZone" },
			{ "definition": { "fragment": { "key": "site-footer", "siteKey": "[$GROUP_KEY$]" } }, "type": "Fragment" }
		],
		"type": "Root"
	},
	"version": 1.1
}

A page selects its master in its own page-definition.json:

"settings": { "masterPage": { "key": "<master-directory-name>" } }
A bare DropZone does not render

{"type": "DropZone"} alone is silently ignored — the master applies, and every page using it shows header and footer with no body. It needs the definition.fragmentSettings block shown above, and version as the number 1.1.

Double chrome

If the theme's own header is still on, your master's header renders under it. Switch the stock chrome off in layout-set/public/metadata.json (lfr-theme:regular:show-header / show-footer) rather than hiding it with CSS — see Themes.

5. Information Template FreeMarker

The newer, type-agnostic cousin of the web content template. Created in Site Menu → Design → Templates → Information Templates for an item type (web content, document, blog, category, object, …) and optionally a subtype. It then appears as a mappable "field" of that item. Map a fragment's HTML editable to it in a display page or a collection item, and the whole item renders through your FreeMarker.

Use it when you want web-content-template-style control over an object entry or a document, which have no web content templates. The limitation is that it's fragment-only: widgets can't use it. restClient is available here too. In an initializer, it is a ddm-templates/ entry whose className is com.liferay.template.model.TemplateEntry, with infoItemClassName / infoItemKey.

6. Widget Template (formerly Application Display Template, ADT)

FreeMarker that overrides a widget's markup: Asset Publisher, Documents and Media, Categories Navigation, Breadcrumb, Site Map, Language selector, Navigation Menu, search results, Knowledge Base. The UI calls them Widget Templates (Site Menu → Design → Templates → Widget Templates). You apply one in the widget's Configuration → Display Template. Since 7.4 they are FreeMarker only; Velocity is gone. The ADT name survives in code and older docs.

<#if entries?has_content>
	<ul>
		<#list entries as curEntry>
			<li>${curEntry.getTitle(locale)}</li>
		</#list>
	</ul>
</#if>
Legacy-leaning

ADTs belong to the widget era. On a modern content page, a Collection Display fragment plus a card template does the same job with a better editor experience. Write ADTs when you are stuck with a widget that has no fragment equivalent.

7. Notification Template

The body of an email or in-app notification. By default it uses term interpolation, where each term is [%OBJECTNAME_FIELDNAME%] in upper case. Copy terms from the editor's Definition of Terms panel rather than typing them:

Your request [%BADAELREQUEST_REQUESTID%] was approved.

Email templates can also switch the editor type to FreeMarker when you need loops or conditionals.

Created via POST /o/notification/v1.0/notification-templates and referenced by ID from a notification object action. Details on Workflow & notifications.

8. Fragment compositions & form templates

Editors can select several fragments on a page and save them as a composition — a named, reusable group that appears in the fragment sidebar. Useful for "our standard CTA block". Like page templates, compositions are copied on use, not linked.

The Form Container plays a similar role for forms: a container bound to an Object, filled with INPUTS-* fragments.

Which one, in one line each

  • Same look for every item of a content type → Web Content Template
  • Every item needs a URL → Display Page Template
  • Same starting layout for new pages → Page Template
  • Same header/footer everywhere, live → Master Page Template
  • A fragment should render a whole object entry / document / item with FreeMarker → Information Template
  • A widget's HTML is wrong → Widget Template (ADT)
  • An email body → Notification Template
  • The whole site, rebuildable from git → Site Initializer
