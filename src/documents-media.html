In one sentence

Documents & Media is Liferay's file repository: folders of files with versioning, check-out, previews, categories, permissions, and a stable URL — and, crucially, a reference that other content points at rather than copies.

Why it is not just a file upload

The common intranet question

"Policy documents with an owner, a department, and a review date" — is that a Document Type or an Object with an attachment field?

Document Type when the file is the thing and the fields describe it. Object when the record is the thing, has a lifecycle or relationships, and the file is one attribute of it. If there is an approval flow, a status, or a link to another record, go Object.

Reference, never copy

Pasting a document's URL as text into a Rich Text field breaks the reference. Move or rename the file and the link 404s, with nothing warning you. Use the Image/Document field type or the media picker so Liferay tracks the relationship.

Listing documents

Documents are assets, so a dynamic collection can select them — filtered by folder, document type, or category — and a fragment renders each row. That is how you build "Policies & Manuals" pages without writing a file browser.

Documents folder "Policies" │ typed as Document Type "Policy" (owner, department, effective date) │ categorised under vocabulary "Department" ▼ Dynamic collection: type = Document, category = HR ▼ Collection Display + policy-row fragment ──▶ page /policies

How it connects

API

POST /o/headless-delivery/v1.0/sites/{siteId}/documents     # multipart upload
GET  /o/headless-delivery/v1.0/documents/{documentId}

Note this module uses the numeric siteId, unlike headless-admin-site which uses the ERC.

Traps

Guest needs VIEW on the folder too

A public page embedding a private document shows a broken image or a 403 download, while the page itself returns 200. Grant VIEW on the folder, and verify with an unauthenticated curl — see Guest access.

Removing a Document Type field orphans its metadata

Same rule as content structures: values are stored keyed by field, so deleting the field makes them unreachable.

Web Content fields in Document Types are gone

Support was discontinued. Any references in old configurations must be removed.
