Collections

The wire that carries "many items" from your data to your page. Three different things are called a collection — this page separates them and shows how each is wired.

Three things named "collection"

NameWhat it isWhere you meet it
Collection (Asset List)A saved, reusable list of items — manual or dynamicSite Admin → Content → Collections
Collection DisplayThe fragment that renders a collection on a pagePage editor sidebar
Fragment collectionJust a folder of fragments. Unrelated to the other two.Site Admin → Design → Fragments

The rest of this page means the first two. The third is covered under Fragments.

The wiring

YOUR DATA THE LIST THE RENDERING ───────── ──────── ───────────── Web Content articles ──┐ Object entries ────────┼──▶ COLLECTION ──▶ Collection Display fragment ──▶ page Documents ─────────────┤ (manual or │ Blog posts ────────────┘ dynamic) ├── how many, how many columns, paging ▲ ├── which fragments render each item │ └── optional Collection Filter fragments │ Collection Provider (custom code supplying items)

Manual vs dynamic

Manual collectionDynamic collection
ContentsItems an editor picked, in an order they choseA saved query — items are matched at render time
Changes when new content is addedNoYes, automatically
Filters onn/aAsset type, structure/subtype, categories and tags, site scope
SortingDrag orderPublish date, title, modified date, relevance
Use for"Featured this month", curated homepage rails"Latest 6 news", "all policies tagged HR"
Both are reusable

A collection is a site-level entity, not a page setting. Define "Latest News" once and place it on the homepage, the news index, and a sidebar — three placements, one definition, one place to change the rules.

Collection Display — what you configure

SettingEffect
numberOfItemsHow many to show (and whether to cap at the collection's own limit)
numberOfColumnsGrid width
paginationTypeNone, numeric, or "load more"
Display — item templateEither a Web Content Template, or fragments you compose per item
List styleGrid, list, or a fragment-based layout

The per-item template

Inside a Collection Display you compose the Collection Item: the fragments rendered once per record. Their editable elements are mapped to the current item's fields rather than to a fixed article. In a page definition that looks like:

{
	"definition": {
		"collectionConfig": {
			"collectionType": "CollectionProvider",
			"collectionReference": { "className": "[$OBJECT_DEFINITION_CLASS_NAME:Policy$]" }
		},
		"numberOfItems": 6,
		"numberOfColumns": 3,
		"paginationType": "numeric"
	},
	"type": "Collection",
	"pageElements": [
		{
			"definition": { "collectionItemConfig": {} },
			"type": "CollectionItem",
			"pageElements": [
				{
					"definition": {
						"fragment": { "key": "policy-card", "siteKey": "[$GROUP_KEY$]" },
						"fragmentFields": [
							{
								"id": "card-title",
								"value": { "text": { "mapping": { "fieldKey": "ObjectField_title", "itemReference": { "contextSource": "CollectionItem" } } } }
							}
						]
					},
					"type": "Fragment"
				}
			]
		}
	]
}

Two details do the real work: fieldKey is ObjectField_<name> for an Object field, and contextSource: "CollectionItem" is what makes the mapping resolve per row instead of per page.

Collection filters

Drop Collection Filter fragments above a Collection Display and visitors can narrow it themselves — by category, tag, or a custom filter. The filter fragment must sit on the same page and targets the display by ID.

For a bespoke filter UI, an fdsFilter CET covers Frontend Data Set tables; for collections, a custom filter fragment plus query params is the usual route.

Collection providers

When neither a manual list nor a query expresses what you need — "the 5 policies this user has not acknowledged", "items from an external API" — a Collection Provider supplies items programmatically. It appears in the collection picker like any other collection.

SourceHowNotes
Liferay ObjectBuilt in — every published object is offered as a collection providerNo code. This is the common case.
Custom logicInfoCollectionProvider in an OSGi moduleSelf-hosted only; needs a deploy
External dataAn Object Entry Manager CET behind an objectPreferred — the object then works as a normal collection source

The canonical index + detail pattern

/news ──▶ Content page └── Collection Display ──▶ dynamic collection "News" └── Collection Item ──▶ news-card fragment (title, image, date) │ └── each card links to… /news/my-article ──▶ Display Page Template bound to the News structure └── fragments mapped to the current item

Build these two things and you have an entire content section. Everything else is styling.

Traps

The list renders empty for visitors and full for you

A Collection Display evaluates item permissions as the visiting user. For object entries, Guest has no VIEW until you grant it at company scope in resource-permissions.json ("scope": "1"). Page-level VIEW does not confer entry-level VIEW. Nothing is logged; the grid is just blank. See Guest access.

Wrong grant scope grants nothing

"scope": "3" only sets defaults for future entries. Several Liferay-internal initializers use it, so it gets copied. Existing entries stay invisible and the handler reports success.

Page composition changes need a reprovision

Adding or rearranging a Collection Display on an existing page is not picked up by re-triggering a site initializer. Pages are upserted, compositions are not retrofitted — delete the site and redeploy.

Do not compute totals in the browser on public pages

A fetch that returns 500 rows for you returns 0 for Guest, with HTTP 200. "500 of 500 seats taken" becomes "0 of 500" — confidently wrong rather than broken. Denormalize with an Aggregation field.
